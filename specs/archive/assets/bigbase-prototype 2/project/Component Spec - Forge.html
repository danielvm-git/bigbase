Forge — Issues, board & labels

Forge is the workspace where engineering work is tracked. It exposes five top-level views: a list of issues, a single-issue detail page, a four-column kanban board, a label manager, and an optional wiki. This spec covers the data shapes, IA, states, and responsive behavior for each.

1. Issues list

The default landing view. Rendered as a dense table — the same pattern as the prototype's Issues page. Clicking a row opens the detail view (section 2).

Columns

  • # — auto-increment ID, monospace, fg-accent
  • Title — truncated to one line; full text on hover
  • Labels — chip stack (max 3 visible, "+N" overflow)
  • Status — open / in progress / review / closed
  • Author — @username
  • Created — relative time (2 days ago)

2. Issue detail

Single-issue page. Composed of three regions: header (title + status selector), body (markdown description), and a comments thread anchored at the bottom.

Header

  • Title — large, editable inline (click to edit)
  • Status selector — 4-option dropdown (open / in progress / review / closed)
  • Label editor — opens the Labels modal (section 4)
  • Assignee — avatar + name

Body

Markdown-rendered description. Edit mode swaps to a textarea with live preview. Supports code blocks (Monaco editor with syntax highlighting — uses the existing Editor component from the storage slice).

Comments thread

  • Each comment shows author, timestamp, body (markdown)
  • Markdown editor at the bottom for new comments
  • Inline reply and edit for own comments

Drag & drop

Cards are draggable across columns. The status field updates on drop. Optimistic UI with rollback on server error.

4. Labels management

Each workspace owns a flat list of labels. Each label has a name and a color (from a fixed palette to keep visual coherence).

Editor

  • Add new label: name (required, unique), color (from palette)
  • Edit existing: same controls, with a Delete button
  • Delete confirms before removing (deletes the label from all issues too)

5. Wiki (optional, v2)

Per-workspace markdown wiki. Out of scope for the v1 release. The v2 design includes a tree-view sidebar (page hierarchy), a markdown editor (Monaco), and a side-by-side preview pane.

6. Empty states

Each view has a tailored empty state. Use the existing EmptyState component.

No issues yet

Create your first issue to start tracking work.

  • Issues list — "No issues yet — Create your first issue to start tracking work." (CTA: + New issue)
  • Kanban — four empty columns, each labeled with the status name; same CTA
  • Labels — "No labels — Create labels to categorize issues"
  • Issue detail — n/a (always at least the issue you opened)

7. Responsive

Forge is desktop-first. The kanban board collapses to a single-column stack on screens < 768px. The issues list drops the Author and Created columns on narrow viewports.

/* ui/src/index.css */
@media (max-width: 768px) {
  .forge-board { grid-template-columns: 1fr; }
  .forge-issue-table th:nth-child(5),
  .forge-issue-table td:nth-child(5),
  .forge-issue-table th:nth-child(6),
  .forge-issue-table td:nth-child(6) { display: none; }
}
