Realtime — Channels, subscriptions & event stream

The Realtime surface gives operators a window into the WebSocket substrate powering the console's live updates. Four views: a connection status banner, an active-channels table, a subscription manager, and a live event log.

1. Connection status

A persistent banner at the top of the Realtime page. Reflects the live state of the WebSocket connection. Clicking the banner opens a detail modal with reconnection controls.

Connected:

Connected to wss://realtime.bigbase.io

Reconnecting:

Reconnecting… (attempt 3 of 10)

Disconnected:

Disconnected — retry in 5s

Behavior

  • connected — green dot, static. Banner can be dismissed.
  • reconnecting — amber dot, pulsing. Banner is sticky.
  • disconnected — red dot, static. Click to retry manually.

2. Channels list

Table of all active WebSocket channels in the current workspace. Auto-refreshes every 2 seconds while the page is open.

Columns

  • Channel — pattern string, monospace, supports wildcards (*)
  • Subscribers — count of active client subscriptions
  • Throughput — events/second over the last 60s
  • Created — relative time
  • Last event — relative time of most recent dispatch

3. Subscription manager

Card per active subscription. Each card shows the channel name, payload filter (if any), and an unsubscribe button. The "New subscription" CTA opens a modal with a channel pattern input and a JSON schema editor for payload filtering.

sites.*
3 events in the last 60s
db.mutations
38 events in the last 60s

Filter editor

The filter is a JSON-schema object matched against the event payload. Example for a sites channel:

{
  "type": "object",
  "properties": {
    "site_id": { "type": "string" },
    "event": { "enum": ["deploy.start", "deploy.success", "deploy.failed"] }
  },
  "required": ["site_id", "event"]
}

4. Event log

Live stream of dispatched events. Tailing log; newest events append to the bottom with a 250ms debounce. Pause button freezes the stream for inspection. The log retains the last 1000 events in memory.

14:23:18.402 sites.deploy.success { "site_id": "marketing", "duration_ms": 12340 } 14:23:18.411 db.mutation { "table": "sites", "row": "marketing", "op": "update" } 14:23:18.420 realtime.metric { "active_connections": 14 } 14:23:18.435 functions.log { "function": "send-email", "level": "info", "msg": "queued 12 jobs" } 14:23:18.451 sites.deploy.start { "site_id": "docs" }

Controls

  • Pause — freezes the stream (new events buffer, not displayed)
  • Clear — clears the in-memory log (does not affect server history)
  • Filter — text input, filters by event type substring

5. Empty states

Each view has a tailored empty state.

No active subscriptions

Subscribe to a channel to start receiving events.

  • Channels — "No channels active" (channels auto-create on first subscriber)
  • Subscriptions — "No active subscriptions — Subscribe to a channel to start receiving events"
  • Event log — "Waiting for events…" (auto-fills as events arrive)
