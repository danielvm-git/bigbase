Responsive specs

Four breakpoints carry the console from a 1440px workstation down to a 375px phone. The content column is capped at ~1180px beside a 252px sidebar; below tablet the sidebar collapses to an icon rail and every multi-column grid folds to one. Spacing tightens in steps — never a fluid blur.

6.1 Breakpoints

Mobile-considerate, desktop-first. Max-width queries; the named tiers below are the design targets.

≥ 1440px
Desktop
  • Full 252px sidebar with labels
  • Content capped ~1180px, centered gutters
  • Dashboard 1.4fr / 1fr two-column
  • Card grids 3–4 across
≤ 1024px
Tablet
  • Sidebar stays full, content padding eases to --space-12
  • Card grids reflow to 2 across (auto-fill minmax)
  • Detail two-columns may stack
  • Tables begin horizontal scroll
≤ 768px
Mobile
  • Sidebar → 64px icon rail (labels hidden)
  • All grids collapse to single column
  • .dash-cols & .metric-grid → 1fr
  • Content padding --space-12 --space-8
≤ 375px
Tiny
  • Page header actions wrap below title
  • Buttons go .btn-block in forms/modals
  • Toasts span near-full width
  • Min hit target held at 44px

The live console ships the primary fold at @media (max-width: 768px) (sidebar → icon rail, grids → 1fr, tighter padding). The 1024px and 375px tiers are refinement targets layered on the same query model.

6.3 Grid & table collapse rules

Every grid is built on auto-fill / auto-fit minmax(), so reflow is largely automatic; the table below names the explicit folds.

Tables scroll, they don't truncate. Wrapping every table in .table-wrap (overflow-x:auto) keeps all columns reachable on small screens rather than dropping data. Sticky first column is a future enhancement, not a column-hide.

6.4 Modal vs. full-page & touch
