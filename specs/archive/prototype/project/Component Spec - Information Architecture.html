Information architecture

The sidebar groups every surface by product area, mirroring the Appwrite Console mental model with BigBase's own scope. Five required groups — Overview, Build, Data, Auth, DevOps — plus one addition (Engage) that gives Messaging a home. Settings and appearance live in the footer. Below: the confirmed tree, the full route map, and the cross-links that stitch flows together.

5.1 Sidebar structure

Confirmed and shipping in the live console. Order is fixed; section labels are uppercase overlines. Each leaf maps to one route.

OVERVIEW
  └─ Dashboard
 
BUILD
  ├─ Sites
  └─ Functions

  ├─ Data Studio
  ├─ SQL Editor
  └─ Storage

  └─ Users
 
ENGAGEadded
  └─ Messaging
 
DEVOPS
  ├─ Git Repos
  ├─ CI / CD
  └─ Monitoring
 
FOOTER
  ├─ Settings · Account / Workspace / Billing
  └─ Appearance · theme picker + dark toggle

Why Engage? The prescribed IA listed no home for the new Messaging screens. Rather than overload Build or Auth, Messaging gets a dedicated ENGAGE group — consistent with how Appwrite treats Messaging as a top-level product. All five required groups remain intact and in order; this is purely additive.

5.3 Cross-links

Surfaces don't live in isolation — these are the documented jumps between areas. Each is a real navigation the shell supports (or should, when wired).

Sites → Git Repos
The Create-site wizard's Source step pulls from connected Git repositories — "Existing BigBase repo" lists the same repos surfaced under Git Repos. Authorizing GitHub here registers the connection globally.
Functions → Monitoring
A function's Logs tab shows recent executions; "View all" / observability deep-links into Monitoring filtered to the functions component for CPU, error rate, and full history.
Dashboard → All areas
Stat cards (Sites, Functions, Git Repos, Users) and the "Jump back in" list are the primary launch points — each routes straight to its area or to sites/new.
Data Studio ↔ SQL Editor
Both read the same collections. The Schema view's tables mirror SQL Editor's table rail; a "Query this" affordance hands a collection to SQL Editor pre-filled.
CI / CD → Git Repos
Each pipeline run names its source repo + branch + commit; the repo link resolves to Git Repos, and a failed run cross-references the triggering site's deployment.
Users → Settings · Workspace
End-users (auth) are distinct from workspace members. The Workspace tab manages team roles (Owner/Admin/Member); inviting a member lives there, not in Users.
Messaging → Functions
Transactional templates are dispatched from functions & events (e.g. nightly-digest sends the digest email). A template's variables map to the payload a function provides at send time.
Sites → Storage
Static build output and uploaded assets resolve against Storage buckets (public-assets); a site's domain serves files the bucket holds.

Cross-links are navigation, not duplication. Each piece of data has exactly one home; links are read-only jumps that preserve context (breadcrumb back-path intact).
