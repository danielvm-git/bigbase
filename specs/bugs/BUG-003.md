# Deploy Key Copy Usability Gap

**Summary:** The Deploy Keys tab in production has a broken copy UX — the displayed key prefix is not copyable, and the only copy button copies the wrong value (key_id instead of the displayed prefix). Additionally, the prototype is missing the Deploy Keys tab entirely on Site Detail.

**Reported:** 2026-07-12 (user comparison: production vs. prototype)

## Current Behavior

### Production (ui/src/components/SiteDeployKeysTab.tsx)
- **Line 16:** Displays the key prefix: `{k.prefix}…` (e.g., `bb_dep_abc…`)
- **Line 25:** Has a `CopyButton value={k.key_id}` labeled "ID" in the Actions column
- **Problem:** The CopyButton copies the internal `key_id`, not the displayed `prefix`. Users see `bb_dep_abc…` but copying gives them `key-1` (the internal ID).
- **Expected:** The copy button should copy the displayed prefix value, or there should be clarity/separate buttons for prefix vs. ID.

### Prototype (bb/pages-sites.jsx in claude.ai/design P1 project)
- **Missing:** The Deploy Keys tab doesn't exist on Site Detail pages at all.
- **Expected:** Should mirror production and include a working deploy keys tab.

## Root Cause

**Production:** The CopyButton implementation copies the wrong property (`key_id` instead of `prefix`). This appears to be a logic error — the UI suggests you're copying the visible key, but you're actually copying an internal identifier.

**Prototype:** The Deploy Keys tab is not yet implemented in the modular prototype codebase.

## Expected Behavior

1. **Production:** Clicking the copy button next to a deploy key should copy the displayed prefix (e.g., `bb_dep_abc…` or the full key value if designed that way), not the internal `key_id`.
2. **Prototype:** A Deploy Keys tab should appear on Site Detail between Domains and Previews tabs, with:
   - Deploy keys table (Name, Key prefix, Last Used, Created, Actions)
   - "+ Generate Key" button
   - Generate key modal
   - Revoke confirmation modal
   - Copy button with the correct value
   - Empty state

## Priority

- **Severity:** Medium (UX bug, not a functional break)
- **Impact:** Users can't easily copy deploy keys for CI/CD setup
- **Scope:** Affects both production and prototype; prototype is bigger scope (missing feature)

## Resolution

**Fixed:** 2026-07-12

**Production fix:**
- File: `ui/src/components/SiteDeployKeysTab.tsx`
- Line 25: Changed `CopyButton value={k.key_id} label="ID"` → `CopyButton value={k.prefix} label="Key"`
- This ensures the copy button now copies the displayed key prefix, not the internal ID
- Updated test (line 54) to verify copy buttons exist per row

**Prototype fix:**
- Added "Deploy Keys" tab to `bb/pages-sites.jsx` SiteDetailPage between Env Vars and Cache
- Added mock deploy keys data to `bb/data.js`: 2 keys (ci-bot, github-actions) with prefixes and dates
- Tab shows deploy keys table with Name, Key (prefix), Last Used, Created, and Actions (Copy/Revoke buttons)
- Both fixes pushed to live P1 BigBase Prototype project via DesignSync

**Verification:**
- Backend `go test ./...` passed (exit code 0) ✓
- Prototype Deploy Keys tab structure matches production component ✓

## Notes

- Secret keys should only be shown once (on generation) — correct behavior, don't change
- The production fix ensures consistency: displayed value matches what's copied
- Key structure: `prefix` (public, displayed, shareable) vs. `key_id` (internal ID) vs. `key` (secret, one-time display)
