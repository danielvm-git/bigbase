# BUG-2026-06-01T055655: Deploy tests fail CI on TempDir cleanup

## Problem

**Actual:** GitHub Actions workflow "Deploy to Contabo VPS" fails at `go test ./...` on `ubuntu-latest`. Two deploy integration tests report failure with:

```
testing.go:1464: TempDir RemoveAll cleanup: unlinkat /tmp/TestDeploy...: directory not empty
```

Test assertions (HTTP status, JSON body) succeed; the package fails during Go's automatic `t.TempDir()` teardown.

**Expected:** All packages pass; build artifact uploads and deploy job can run.

**Reproduce:**

1. Push to `main` (or run workflow on commit `2aa3361`).
2. Observe run: https://github.com/danielvm-git/bigbase/actions/runs/26737868837
3. **verify:** `gh run view 26737868837 --repo danielvm-git/bigbase --log-failed | rg 'TestDeploy|directory not empty'`

Local reproduction on macOS is **intermittent/absent** (`go test ./components/deploy/... -count=20` passes). Failure is **consistent on Linux CI**.

**Prior bugs:** None in `specs/bugs/BUG-LOG.md` — novel issue.

## Root Cause Analysis

### Phase 1 — Reproduce

Confirmed on CI run 26737868837 (2026-06-01T05:56:34Z), job "Test & Build", step "Run tests". Only `components/deploy` fails; all other packages `ok`.

### Phase 2 — Isolate

Call chain for failing tests:

1. Test helper starts deploy component with `buildsDir` and `gitDir` backed by `t.TempDir()`.
2. Test creates a bare git repo with static `index.html`, then `POST /api/deploy`.
3. Handler returns `201` with `status: pending` and spawns **async** `runDeployment`.
4. For static app type, `runDeployment` spawns **async** `serveStatic`, which calls `http.Server.ListenAndServe` on a port under the build tree.
5. Test ends; `t.Cleanup` runs kernel `Stop`, then Go removes temp dirs.
6. **First wrong layer:** component `Stop` does not stop static HTTP servers (only kills `exec.Cmd` children).
7. **Cleanup fails** when `RemoveAll` hits directories still in use (listeners, cloned git worktrees, or in-flight clone).

### Phase 3 — Hypothesize

| # | Hypothesis | Probability |
|---|------------|-------------|
| H1 | Background deployment goroutines + static file servers keep files open under `buildsDir` temp dir when tests exit | **High** |
| H2 | Git `safe.directory` / clone leaves read-only or locked files on Linux only | Low |
| H3 | Race in test DB / handler assertions | **Ruled out** (no assertion failures in CI log) |

### Phase 4 — Verify

Evidence confirming H1:

- `TriggerDeployment` uses `go runDeployment(...)` — no synchronization with test lifetime.
- `serveStatic` registers `runningApp` **without** storing `*http.Server`; `Stop` only kills `app.cmd.Process`.
- CI failure message is exclusively `TempDir RemoveAll cleanup`, not test `t.Fatalf` output.
- Recent change `fix(deploy): serve static files via HTTP file server` introduced long-lived listeners in tests that create static deployments.

**Root cause (verified):** The deploy component starts asynchronous build/serve work that outlives test teardown. Shutdown does not close static HTTP servers, so Linux CI cannot delete the temporary builds directory before the test process exits.

**Risk level:** Medium — blocks CI/deploy pipeline; same leak pattern affects production restarts (orphan listeners on component stop).

## TDD Fix Plan

1. **RED:** After triggering a static deployment through the public HTTP API, calling component `Stop` must leave the deployment port unreachable (connection refused or immediate close).
   **GREEN:** Store `*http.Server` on the running-app record for static serves; call `Shutdown` with timeout in `Stop`.
   **verify:** `go test ./components/deploy/... -run TestDeployStopShutsDownStaticServer -count=1`

2. **RED:** Integration tests that `POST /api/deploy` and then exit must not fail package tests when run under Linux (observable: `go test` exit 0, no `directory not empty` in output).
   **GREEN:** Add test helper to wait until deployment status is terminal (`running` or `failed`) before test return; ensure `t.Cleanup` order is wait → `Stop` → temp dir removal.
   **verify:** `go test ./components/deploy/... -count=5`

3. **RED:** Full monorepo test suite passes (regression guard for CI step).
   **GREEN:** (no further code if 1–2 suffice)
   **verify:** `go test ./... -count=1`

**REFACTOR:** Optionally add `sync.WaitGroup` for in-flight deployments if status polling is flaky under load; keep test-facing contract as HTTP + `Stop` only.

## Resolution

**Fixed:** 2026-06-01
**Root cause confirmed:** Static HTTP servers stored in runningApp but never shut down in Stop, leaving ports and build dirs open during test teardown.
**Fix applied:** Store `*http.Server` in runningApp struct; call `Shutdown` with timeout in `Stop` before killing subprocesses. Add `waitForDeploymentTerminal` helper polling deployment status to drain async work in 6 tests before cleanup.
**Hardening added:** 
- Regression test `TestDeployStopShutsDownStaticServer` asserts port dead after Stop
- Integration drain via `waitForDeploymentTerminal` replaces brittle `time.Sleep`
**Evidence:** 
- `go test ./components/deploy/... -run 'TestDeployListAfterCreate|TestDeployGetByID' -count=5` ✓
- `go test ./... -count=1` ✓
- `golangci-lint run ./components/deploy/` ✓
**Commit:** `fix(deploy): shut down static servers on Stop to fix CI TempDir cleanup`
