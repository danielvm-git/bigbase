# BUG-2026-06-20T125952: MCP SSE connection fails with 405 Method Not Allowed

## Problem

Pi's MCP adapter cannot connect to the BigBase MCP server. The client sends a GET
request to establish an SSE stream (per MCP Streamable HTTP protocol), and the
server responds with `405 Method Not Allowed`.

**Actual behavior:** `GET /mcp` → `405 Method Not Allowed`
**Expected behavior:** `GET /mcp` → `200 OK` with SSE `text/event-stream` content-type
**How to reproduce:** `curl http://localhost:3900/mcp` or connect any MCP Streamable
HTTP client (pi-mcp-adapter, Claude Desktop, etc.)

## Root Cause Analysis

The MCP component's HTTP handler for `/mcp` rejects every method except POST:

```
if r.Method != http.MethodPost {
    http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
    return
}
```

The MCP Streamable HTTP protocol (2025-03-26) specifies three HTTP methods on the
message endpoint:

- **GET** — Establish an SSE stream for server→client notifications
- **POST** — Send JSON-RPC requests and receive responses
- **DELETE** — Terminate the session

The `mcpsdk.NewStreamableHTTPHandler` already handles all three methods correctly.
The wrapper's POST-only guard blocks the SDK handler from ever seeing GET or DELETE
requests.

**Contributing factor:** The handler comment says "Routes: POST /mcp — MCP messages"
which suggests the developer assumed POST was the only valid method. This is
incorrect for Streamable HTTP.

**Risk level:** Medium — blocks all MCP client connections via HTTP/SSE.

## Resolution

**Fixed:** 2026-06-20
**Root cause confirmed:** The `/mcp` HTTP handler had a POST-only method guard that blocked
GET requests required by the MCP Streamable HTTP protocol for SSE session establishment.
**Fix applied:** Removed the `if r.Method != http.MethodPost` guard, updated the route
documentation comment, and corrected the `TestHTTPTransport` assertion that incorrectly
expected 405 for GET.
**Hardening added:** `TestMCPGetSSE` verifies GET /mcp never returns 405.
**Evidence:** All 24 packages pass; GET /mcp now returns 400 with session guidance (not 405).
**Commit:** `fix(mcp): allow GET /mcp for SSE connections (remove 405 method guard)`
