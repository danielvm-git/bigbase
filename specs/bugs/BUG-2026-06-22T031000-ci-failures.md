# BUG-2026-06-22T031000: CI failures — test branch name assumption + stale allure-report-action SHA

## Problem

Two distinct CI failures on `main`:

1. **`TestSiteManifestGetAndSave` fails** on both SQLite and PostgreSQL test legs:
   - Actual: `sites_test.go:541: expected status 200, got 500: {"error":"git show failed: fatal: invalid object name 'main'."}`
   - Expected: Test passes (HTTP 200).
   - Affected since: commit `03a01e2` (e40s03 — this test was introduced).

2. **`Generate Progress Dashboard` fails** on the Allure Report generation step:
   - Actual: `docker.io/library/openjdk:8-jre-alpine: not found` — Docker build fails because the base image `openjdk:8-jre-alpine` has been removed from Docker Hub.
   - Expected: Allure report is generated successfully.
   - Affected since: commit `e8d8e77` (or whenever Docker Hub removed the image).

## Root Cause Analysis

### Failure 1: Test branch name assumption

`TestSiteManifestGetAndSave` creates a bare git repo (`git init --bare`), clones it, makes an initial commit, and pushes to `main`:
```
git push origin main
```

This assumes the local branch created by `git init` + `git commit` is named `main`. This depends on the `init.defaultBranch` git config, which defaults to `main` in Git ≥2.28 but may vary across CI runner images. On the GitHub Actions `ubuntu-24.04` runner, the default branch after `git init --bare` is `main` with Git 2.54, but the `git clone` of an empty repo followed by `git commit` may produce a local branch named `master` depending on runtime config. When this happens, `git push origin main` fails silently (the error is discarded by `_ = cmd.Run()`), leaving the bare repo with no `main` ref. The subsequent `git -C <bare> show main:bigbase.yaml` then returns `invalid object name 'main'`.

The test passes locally because `git config --global init.defaultBranch` is set to `main`, but the CI runner may not have this setting present.

**Risk level**: Low — test environment-specific, not a production bug.

### Failure 2: Allure report Docker image removal

The workflow pins `simple-elf/allure-report-action@e3e158032c1140676ea295a073942850d68bae29`, which corresponds to v1.7 (July 2023). This version's Dockerfile uses `FROM openjdk:8-jre-alpine`. The `openjdk:8-jre-alpine` image has been removed from Docker Hub (Java 8 is long EOL), causing the Docker build to fail with `not found`.

The latest version v1.14 (SHA `e463a472d3b1d750f9544369d60589ff1964c820`, released May 2026) uses a newer Java base image that is still available.

**Risk level**: Low — third-party dependency version pin, straightforward update.

## Resolution

**Fixed:** 2026-06-22

**Root cause 1 (test failure):** Two issues:
- The test's `git push origin main` assumed the local branch was named `main`, but on CI the default branch may be `master` due to `init.defaultBranch` config differences. Fixed by adding `git branch -M main` before push.
- `commitManifestToRepo` was running `git config user.name/user.email` without `.Dir = tempDir`, so the config was applied to the bigbase repo instead of the temp clone. When global git config was absent (CI), `git commit` failed with "Author identity unknown". Fixed by restoring `.Dir = tempDir`.

**Root cause 2 (allure report):** `simple-elf/allure-report-action` pinned to v1.7 used `FROM openjdk:8-jre-alpine`, which has been removed from Docker Hub. Updated pin to v1.14 (SHA `e463a47`).

**Fixes applied:**
- `.github/workflows/ci.yml`: updated allure action SHA from e3e1580 (v1.7) to e463a47 (v1.14)
- `components/sites/sites_test.go`: added `git branch -M main` before push in `TestSiteManifestGetAndSave`; added `debugLoggerForTest` to expose git errors in CI output
- `components/sites/sites.go`: restored `.Dir = tempDir` on git config commands in `commitManifestToRepo`

**Evidence:** All 3 CI jobs pass (sqlite, postgres, dashboard). PR #39.
