# BUG-20260628T050000: Anonymous tokens can write/delete records

## Problem

Anonymous tokens (role=anonymous) pass through the auth middleware bypass but are NOT restricted to read-only operations. The API handler (`components/api/api.go`) dispatches POST, PATCH, and DELETE requests without checking `UserRoleFromContext`. Anonymous users can create, modify, and delete records in any collection under `org_id=0`.

**Actual:** POST/PATCH/DELETE with anonymous token → 200/201 (write succeeds)
**Expected:** POST/PATCH/DELETE with anonymous token → 403 Forbidden
**Security impact:** HIGH — unauthorized data modification/deletion

## Root Cause Analysis

The auth middleware bypass for anonymous tokens (added in e49s01) correctly skips org isolation and email verification, but does not restrict HTTP methods. The API handler (`handleCollection` in api.go:166) has a method dispatch switch with no role check. The only role check in api.go is for admin-only operations (line 492).

This is a design flaw: the middleware trusts that downstream handlers will enforce anonymous restrictions, but the API handler was never designed to handle anonymous users.

## Resolution

**Fixed:** 2026-06-28
**Root cause confirmed:** Anonymous auth middleware bypassed org checks but didn't restrict HTTP methods, and API collection handlers did not enforce read-only role checks.
**Fix applied:** Restrained anonymous tokens to GET, HEAD, and OPTIONS requests directly in the auth middleware's anonymous bypass block.
**Hardening added:** Added test cases for POST, PATCH, and DELETE requests with anonymous tokens, asserting they are rejected with 403 Forbidden.
**Evidence:** all tests pass (`go test ./...`)
